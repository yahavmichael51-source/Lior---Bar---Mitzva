# אתר אישור הגעה לבר המצווה

אתר קטן ומותאם לטלפון: אורחים ממלאים שם פרטי ובוחרים ״מגיע/ה״, ״לא מגיע/ה״ או ״עוד לא יודע/ת״. מי שבוחר ״מגיע/ה״ בוחר גם כמה אנשים יגיעו: ״רק אני״, ״אני + 1״ עד ״אני + 4״ (1 עד 5 אנשים), או ״אחר״ וכותב את המספר הכולל (עד 30).

- **עמוד האורחים:** `/`
- **דף הניהול (סטטיסטיקה ונתונים):** נמצא בקישור נפרד, `/nihul-lior`, שלא מופיע באתר של האורחים. כשנכנסים אליו מופיע מסך כניסה עם שם משתמש וסיסמה. אפשר להגדיר עד שני משתמשים: `ADMIN_USERNAME` ו־`ADMIN_PASSWORD`, ובנוסף `ADMIN_USERNAME_2` ו־`ADMIN_PASSWORD_2`.

האתר לא מאחד תשובות של אורחים עם אותו שם. כל שליחה נשמרת כשורה נפרדת.

אורחים ממלאים שם פרטי ושם משפחה. אורח ששינה את דעתו פותח שוב את הקישור מאותו טלפון, רואה את התשובה ששלח ולוחץ ״שינוי תשובה״. הטלפון שומר קוד פרטי לכל תשובה, ורק מי שמחזיק בקוד יכול לשנות אותה. אם אורח עונה מטלפון אחר וממלא את אותו שם פרטי ושם משפחה, האתר מציג את התשובה הקודמת ושואל אם זה הוא. אם יבחר ״כן, זה אני״, התשובה הקודמת מתעדכנת ולא נוספת שורה חדשה. אם יבחר ״אני אדם אחר עם אותו שם״, נשמרת תשובה נפרדת.

כל שינוי בתשובה נשמר בהיסטוריה. בדף הנתונים מופיעה התשובה הנוכחית, ומתחתיה כל התשובות הקודמות ומתי שונו, כולל שינויים שעשה המנהל. יש מונה ״אורחים ששינו את התשובה״, סינון ״רק מי ששינה תשובה״ ועמודת ״תשובות קודמות״ בקובץ ה־CSV. הספירות מתבססות רק על התשובה הנוכחית.

## פרסום ב־Netlify (מומלץ: חינם, תמיד זמין ונפתח מיד)

ב־Netlify העמודים נטענים מיד ולא ״נרדמים״. התשובות נשמרות ב־Netlify Blobs, האחסון המובנה של Netlify, ולכן לא צריך לפתוח מסד נתונים נפרד.

1. נכנסים ל־[app.netlify.com](https://app.netlify.com) עם חשבון GitHub.
2. בוחרים **Add new project** ואז **Import an existing project** ו־**GitHub**, ובוחרים את המאגר `Lior---Bar---Mitzva`.
3. ב־**Branch to deploy** בוחרים את הענף שרוצים לפרסם. את שאר ההגדרות משאירים כמו שהן, כי הקובץ `netlify.toml` כבר מגדיר הכול.
4. לפני הלחיצה על Deploy, או מיד אחריה ב־**Project configuration ← Environment variables**, מוסיפים:
   - `ADMIN_USERNAME`: שם המשתמש לדף הנתונים (חובה)
   - `ADMIN_PASSWORD`: הסיסמה לדף הנתונים (חובה)
   - `SESSION_SECRET`: מחרוזת אקראית ארוכה (מומלץ)

   אם הוספתם אותם אחרי הפריסה, צריך להריץ פריסה מחדש: **Deploys ← Trigger deploy**.
5. אפשר לשנות את הכתובת ב־**Project configuration ← Change project name**, למשל `lior-bar-mitzva.netlify.app`.
6. נכנסים ל־`/nihul-lior`, פותחים את ״פרטי האירוע שמוצגים לאורחים״ וממלאים תאריך ומיקום.
7. שולחים לאורחים את הכתובת הראשית.

כל דחיפה לענף שנבחר מעדכנת את האתר אוטומטית, והתשובות שכבר נשמרו נשארות.

## הפעלה על שרת Node רגיל (אופציונלי)

אפשר להריץ את האתר גם על כל שרת Node, למשל במחשב שלך או ב־Render (`render.yaml`). במקרה הזה הוא שומר ב־PostgreSQL אם מוגדר `DATABASE_URL`, ואחרת בקובץ SQLite מקומי.

| משתנה | מה זה |
|---|---|
| `ADMIN_USERNAME` | שם המשתמש לדף הנתונים (חובה) |
| `ADMIN_PASSWORD` | הסיסמה לדף הנתונים (חובה) |
| `DATABASE_URL` | כתובת חיבור ל־PostgreSQL. בלי המשתנה הזה התשובות נשמרות ב־`data/rsvp.db` |
| `SESSION_SECRET` | מחרוזת אקראית לחתימה על עוגיית ההתחברות |
| `PORT` | ברירת המחדל היא 3000 |

```bash
npm install
ADMIN_USERNAME=avishay ADMIN_PASSWORD=הסיסמה-שלי npm start
# ואז לפתוח את http://localhost:3000 ואת http://localhost:3000/nihul-lior
```

> באירוח חינמי של Render השרת ״נרדם״ אחרי זמן בלי כניסות, והדיסק נמחק בכל הפעלה מחדש. לכן Netlify עדיף לאתר הזה.

## בדיקות

```bash
npm install
npm test    # בדיקה מקצה לקצה בדפדפן: פעם מול שרת Node עם SQLite, ופעם מול הדמיה של Netlify עם Blobs
TEST_DATABASE_URL=postgres://... node test/e2e.js   # אותה בדיקה מול Postgres
```

הבדיקה שולחת תשובות מכל האפשרויות, כולל ״אני + 1״ עד ״אני + 4״ ו״אחר״, ובודקת שהספירה מדויקת. היא גם בודקת שהתשובות מופיעות בדוח המנהל אחרי רענון, ושהסינון, ייצוא ה־CSV, העריכה, המחיקה וההגנה בסיסמה עובדים.
